# Artifact section templates

Use only the template for the active artifact and replace every placeholder honestly.

## `spike.md`

Title; Idea; Why worth developing; Provenance; Known assumptions; Unresolved questions; Confidentiality concerns; Research decision and rationale.

## `research-report.md`

Scope/date; Verified facts (claim + source); Disputed claims; Interpretation (clearly labeled); Unresolved claims; Useful interview questions.

## `interview.md`

Before asking: question, functional lens, material already obtained, missing coverage
targeted, and `Answer: pending`. After the response: replace the marker with the human
answer and record obtained, missing, and next move.

## `content-brief.md`

- Social: central thesis, strongest examples, factual support, creator reasoning,
  tension/objection, practical or forward-looking payoff, important interview wording,
  confidentiality constraints, possible angles, and unresolved weaknesses. Keep channel
  structure out of the shared brief.
- README: target readers, primary promise, reader problem, desired action, key proof,
  required sections, important commands, public claims requiring verification, tone,
  avoidances, limitations, and unresolved questions.

## `draft-NN.md`

- LinkedIn: three hook options; main body; three closing options; recommended assembled
  version; Unicode character count; factual/confidentiality flags; uncertainties.
- X: selected variant marker; useful opening options; one `Recommended final version`
  section using the canonical post headings; per-post counts; factual/confidentiality
  flags; distinct angles for standalone posts; argumentative function for thread posts.
- README: a complete proposed README grounded in repository evidence and owner input.
  Include only useful sections. Character count is optional information, never a quality
  measure.

## `council-NN.md`

Human authorization/request record; what works; blocking findings; consensus (name at least two supporting lenses); six lens observations and scores; overall diagnostic score and scale; ranked revision plan; exactly one recommended route.

For README Council use positioning, first-minute comprehension, onboarding, technical
accuracy, trust and credibility, and voice and readability. Also record optional taste
suggestions and exact inaccurate claims or commands.

For X Council use immediate clarity, point of view, compression, specificity/credibility,
voice authenticity, and platform fit. Separate blockers, consensus, taste, unnecessary
cleverness, engagement bait, unsupported claims, and repetition inherited from a primary.

## `revision-plan-NN.md`

Source feedback; ranked changes with reason; deliberately unchanged items; risks; approval status.

## `final.md`

- LinkedIn: approved post; selected hook/closing; character count; remaining caveats;
  explicit approval status/date.
- X: approved recommended version in the same mechanically valid structure as the draft,
  plus variant, per-post character counts, flags, and approval status/date.
- README: exact approved README content. Record approval and the target path in the current
  revision plan or Council artifact before applying it to the target file.

## `lesson-candidates.md`

At most five numbered candidates, each with evidence, generalized lesson, scope
(`creator-wide voice`, `social workflow`, `LinkedIn`, `X`, `README`, or `this run only`),
does-not-apply boundary, confidence, and approval status (`pending` initially).

## `parking-assessment-NN.md`

Run ID/date; what remains promising; strongest material collected; why the run is not being
completed; what is missing; recommended next step; recommendation to resume or reconsider
from a new angle. This is a preservation assessment, not a failure score.
