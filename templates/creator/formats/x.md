# X format guidance

## Canonical constraints

- Supported variants: `single`, `thread`, and `standalone`.
- A `single` contains one independently understandable post.
- A `thread` contains two or more sequential posts that form one argument.
- `standalone` contains two or more posts that each stand alone and use a genuinely
  different angle or framing.
- The deterministic per-post limit is 280 Unicode code points. Validate the recommended
  version with `bin/cf validate-x`.
- Drafts and finals declare exactly one variant with
  `<!-- cf:x-variant: <variant> -->` and put mechanically validated copy under
  `## Recommended final version`.
- Within that section use `### Post` for a single post, sequential `### Post N` headings
  for a thread, or sequential `### Standalone N` headings for multiple standalone posts.

Do not assume every idea should become a thread. When the creator has not selected a
variant, recommend one from the shared brief and ask for confirmation before drafting.

## Draft output

- A single-post draft may include several openings, one recommended version, its character
  count, factual/confidentiality flags, and an optional alternate close.
- A thread identifies the function of each post, reports the total count, validates every
  post, and includes factual/confidentiality flags.
- Standalone posts must not read like slices of a thread. Record their distinct angles and
  shared run provenance.

## X Writer's Council

Use one structured review after human authorization:

1. Immediate clarity.
2. Strength of point of view.
3. Compression.
4. Specificity and credibility.
5. Voice authenticity.
6. Platform fit for the selected variant.

Separate blocking issues, consensus findings, optional taste changes, unnecessary
cleverness, generic engagement bait, unsupported claims, repetition inherited from a
primary format, and diagnostic scores. Do not revise automatically.
